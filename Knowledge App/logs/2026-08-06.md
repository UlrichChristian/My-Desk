## 13:59 — My Desk / ASO cross-login bug fixed
**Symptom:** logging into My Desk (:5002) logged you out of the ASO app (:5000), and vice versa.

**Cause:** browser cookies are scoped by *host*, not host+port. `127.0.0.1:5002` and `127.0.0.1:5000` share one cookie jar. Both apps used Flask's default cookie name `session` but different signing keys (`C_APP_SECRET_KEY` vs `ASO_SECRET_KEY`), so each app overwrote the other's cookie and then failed the signature check — Flask silently discards an unverifiable session cookie and shows the login page.

**Fix:** set `SESSION_COOKIE_NAME = "cdesk_session"` in `c.py` `create_app()`. Only one side needs a distinct name; ASO keeps `session`. Verified with the Flask test client: My Desk now issues only `cdesk_session`.

**Known, accepted:** `c.py:38` falls back to `os.urandom(32)` when `C_APP_SECRET_KEY` is unset, so My Desk mints a new signing key on every restart and logs you out. There is no `.env` in `C:/Christian` and nothing loads dotenv. ASO has a `.env` with `ASO_SECRET_KEY`, which is why only My Desk lost sessions on restart. Christian decided not to fix this — the restart logout is acceptable for a local single-user app. Don't re-raise it. (If it ever matters, the fix is to persist a generated key to a gitignored file on first run.)

## 16:54 — Focus Board: "category" is four different things
Confusion surfaced while trying to move a task between board sections. Four distinct
groupings, only one of which responds to the urgent/important flags:

1. **Do Now / Schedule / Delegate / Later** — driven by `important` + `urgent`
   (`focus_web/routes.py:180`). Changed via the edit form's checkboxes *or* by dragging
   the tile; a drop rewrites the flags (`routes.py:338`). Only rendered inside the To-do
   column — Projects and Recurring tasks carry the flags but show no quadrants.
2. **To-do / Projects / Recurring** — the resolved *type* (`focus_services/tasks.py:53`),
   derived from project assignment / recurring origin, forced via the "Type override"
   select.
3. **Today / Active / Pipeline / Completed** — the lifecycle *band*, drag-and-drop only.
4. **Category / Subcategory coloured labels** — the `categories` table, a labelling and
   colour taxonomy with no effect on board placement.

**UX trap (this is what caught Christian):** a task whose due date has arrived or passed is
force-promoted to **Do Now** regardless of its flags (`routes.py:174-181`). Unticking
Important/Urgent appears to do nothing, because the due date wins and nothing on the tile
explains why. Workaround is to clear or push out the due date.

Possible improvement, not built: surface the reason on the tile — e.g. a "due" marker on
promoted tiles, or disable/annotate the flag checkboxes when a reached due date is
overriding them. The board already computes `row["due_reached"]` (`routes.py:179`), so the
signal is available to the template.
