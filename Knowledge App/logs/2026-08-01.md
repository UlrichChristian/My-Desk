## 16:20 — Video support + live transcription POC
Built a proof-of-concept (planning + working code) in Temp, NOT in My Desk:
`OneDrive - Effortless Admin Inc/Temp/video-support-poc/`.

What it does: bare-bones site a visitor connects to and clicks "Request live
support" -> two-way browser video call with Christian -> conversation transcribed
live, labeled You/Visitor, with copy-in-chunks buttons to paste into a Claude
chat (Claude answers via existing MCP servers; that step is human-in-the-loop,
not integrated).

Stack (zero API tokens, all free/browser-native):
- Flask + flask-sock (pure-Python WebSocket; picked over Flask-SocketIO because
  eventlet/gevent are flaky on the machine's Python 3.14). Own venv in the folder.
- WebRTC for peer-to-peer video (server only relays SDP/ICE, never media).
  Google public STUN, no TURN.
- Web Speech API for transcription (each browser transcribes its own mic).

Port note: :5000 is already occupied by another login-protected Flask app on this
box, so the POC defaults to :5050 (override via POC_PORT env).

Verified: all routes 200; automated 2-client WebSocket relay test passes
(join handshake, offer/answer/ICE, transcript relay, peer-left); both pages render
and client JS loads clean. Not verifiable headless (needs a real device): live
camera video + speech transcription — Christian to confirm in a two-tab test.

Limitations flagged: Chrome/Edge only; Web Speech sends audio to Google (not for
real client PII as-is — local Whisper later); camera needs localhost or https, so
a real remote person needs an ngrok/cloudflared tunnel; single session at a time.

## 16:45 — POC add: one-click "Send to Claude"
Added a one-click send from the host transcript panel into Claude Desktop.
No API token involved (there isn't one): the local Flask server exposes
`/to-claude`, which runs `send_to_claude.ps1` to focus the Claude Desktop window,
paste the since-last chunk, and press Enter. Lands in Claude Desktop where the MCP
servers actually live (web app wouldn't have them).

Guarded by a per-session token embedded only in /host, so a remote visitor over a
tunnel can't trigger keystrokes on Christian's machine. Verified: 403 without token;
dry-run WITH token returned `dryrun-ok` (script found the live Claude Desktop window
but sent no keys — deliberately didn't fire real paste+Enter into his chat). Button
renders, no JS errors. Real paste+send left for Christian to confirm.

Caveats: Windows-only (PowerShell SendKeys); Claude Desktop must be running; types
into whatever field Claude has focused.
